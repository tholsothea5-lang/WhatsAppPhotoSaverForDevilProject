This page is a static build on GitHub Pages. The script runs inside the web.whatsapp.com tab you already have open, not here. There is no server and no password.
  1. Open WhatsApp Web — go to web.whatsapp.com and wait for your chats to load.
  2. Open DevTools — press Ctrl+Shift+J (Windows/Linux) or ⌥+⌘+J (Mac). Switch to the Console tab.
  3. Allow pasting once — if Chrome shows a warning, type allow pasting and press Enter. You only do this once.
  4. Paste and run — click Copy script to clipboard above, paste (Ctrl+V) into the console, press Enter. A panel appears in the corner of WhatsApp Web. Pick a chat and date range, Scan, then Download ZIP.
Tip: To use it again later without reopening this page, DevTools → Sources → Snippets → New snippet, paste the script once, and run it with Ctrl+Enter (it stays saved). If you reload WhatsApp Web you'll need to run it again.

One folder per chat, then per day, then per caption. Album photos share the album's caption, and photos without one go to No caption. Filenames are sender_date_time_hash.ext so re-downloading won't overwrite.

Captions included

Reads captions from WhatsApp's live message models, including album captions.

Videos are opt-in

Tick "Include videos" to pull MP4s with the same layout and naming.

Safe re-runs

Short hashes keep filenames unique; failed downloads (expired media) are reported and skipped.

Runs entirely locally

Decrypts in memory with WebCrypto, builds the ZIP in the tab, and your browser saves it. No uploads.

Questions

Why the console, not a bookmarklet?

WhatsApp Web uses a strict Content Security Policy that blocks javascript: bookmarklets. The browser's DevTools console is exempt from that CSP, so pasting the script there is the standard, zero-install workaround. The code is identical to what was tested against real WhatsApp Web.

Is this safe?

Nothing leaves the browser. The script reads WhatsApp's own local storage and CDN, decrypts media in memory, and creates a ZIP download. There is no network call to a third-party server. You are only running code you copied from this page on your own WhatsApp Web session.

Why do some photos fail to download?

WhatsApp Web only has media cached that it has loaded on this device, and older media expires from WhatsApp's servers (HTTP 404/410). Those are reported as failures and the ZIP still contains everything that downloaded successfully.

Chrome says "Don't paste code..."

That's Chrome's built-in self-XSS protection. If you copied the script from this page and understand what it does, type allow pasting into the console and press Enter. After that you can paste normally for this profile.

Does this work on Firefox or Edge?

It has been tested in Chromium-based browsers (Chrome, Edge). Firefox's console works in a similar way, but some APIs can differ. If something breaks on Firefox, use Chrome/Edge for best results.

Before you use it

Use it on your own account. This runs in your own WhatsApp Web session and is outside WhatsApp's terms of service — use it only with your own account and at your own risk. WhatsApp updates can change internals and break it. Respect the privacy of others before sharing an export.
